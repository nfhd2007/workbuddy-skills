# 限时周测：读图判断、时间预算与分档作答

> 适用：整卷一个总时钟、归零自动交卷、不带监考 / 考试码 / 抓拍的作业性质周测。
> 详细标定与坐标见 `itest-ui.md`，本文件只管「时间怎么管」。

## 一、为什么必须分档

本技能的整条流水线是在一份**不限制时长**的听力训练卷上标定的：一屏一循环、每步截图复核、双答案交叉、文本题量化后多轮打磨、填空题整篇收齐再解、听力回环录制 + 云端转写。实测整卷音频 26 分钟、加上操作间隔 41 分钟。这些设计在无限时卷上是追求正确率的合理取舍，在限时卷上会吃掉几乎全部预算。

**归零后平台自动交卷，不可撤销，未答题直接空白。** 所以限时的目标不是「做到最好」，而是「在规则允许的时间内把卷子填满，来不及就如实告知并安全收尾」。

用户已确认的取舍：**接受「先保底填满、存疑题后补」**。

## 二、运行时读图判断（不要沿用上一卷结论）

进入答题页后，第一张截图必须判定计时形态，写进 `screen.json` 的 `timer` 字段：

| 形态 | 页面特征 | `timer.mode` | 后果 |
| --- | --- | --- | --- |
| 倒计时（整卷总时钟） | 顶部显示 `剩余时间 44:58` 一类**递减**数字，或「考试剩余时间」 | `countdown` | 归零自动交卷，必须走时间预算 |
| 正向计时（无限时训练卷） | 顶部从 `00:00:00` 往上走 | `countup` | 无自动交卷风险，走 `full` |
| 读不清 / 被遮挡 / 没有计时条 | — | `unknown` | **一律按限时保守处理**，并重新截图确认；不得默认成无限时 |

判据补充：

- 常见是**整卷一个总时钟**；若发现每个 Section / 每题各有独立倒计时，按**最短的那个**当预算，并在回报里说明。
- 显示格式可能是 `mm:ss`、`hh:mm:ss`、截止时间（如 `21:58 前提交`）或纯文字。换算成秒写进 `remainingSeconds`；截止时间用当前时间差换算。
- `autoSubmit` 固定按 `true` 处理（用户已确认归零自动交卷），除非本卷页面明确写了「时间到仅提示」。
- 总题量 `totalQuestions` 从答题卡 / 进度条读；读不到就留 0，`budget` 会退化成按屏估。
- **每卷重新判一次**。上一卷是无限时，不代表这一卷是。

`screen.json` 示例片段：

```json
"timer": {
  "mode": "countdown",
  "display": "剩余时间 44:58",
  "remainingSeconds": 2698,
  "autoSubmit": true,
  "totalQuestions": 40,
  "answeredQuestions": 0
}
```

## 三、两条命令形成闭环

```bash
# 进入答题页第一屏：读图后把计时快照落盘（只需首屏一次，后续 clock 会保留 startedAt）
scripts/run.sh clock --screen shots/screen1.json

# 之后每一屏循环开头跑一次，自动算剩余并给出模式
scripts/run.sh budget --answered 6
```

- `clock` 写 `shots/clock.json`：计时形态、抓取时刻的剩余秒数、推算出的截止时间、是否自动交卷、题量。**首屏之后不必每屏重读秒数**——`budget` 用 `deadlineAt - now` 推算当前剩余；只有页面倒计时明显与推算不符（例如被暂停过、换卷）才重新 `clock`。
- `budget` 写 `shots/budget.json` 并打印：剩余 / 已用 / 每题均耗 / 预计还需 / `[MODE=...]`。**照 `[MODE=]` 执行，不要自己拍脑袋**。
- `guard` 也会读 `shots/clock.json`，在红线检查之外附带打印同一模式提示，防止漏跑 `budget`。

`clock` 也支持不写 `screen.json` 直接传参，用于快速补录：

```bash
scripts/run.sh clock --mode countdown --remaining 2700 --total 40 --answered 0
```

## 四、三档模式（`budget` 自动选，不硬编码时长）

时长不固定，所以**不预设「45 分钟」之类的常量**。阈值全部由「剩余时间」与「本题实测进度」动态算出来：

| 模式 | 触发条件 | 做什么 |
| --- | --- | --- |
| `full` | `countup`；或 `countdown` 且 `剩余 ≥ 预计还需 × 1.5` | 现有完整流水线：双答案交叉、答案守恒、文本量化多轮、逐屏截图复核 |
| `timed` | `countdown` 且 `剩余 < 预计还需 × 1.5`；或 `unknown` | 砍掉所有可砍的质量关卡，优先保覆盖率；只保留一次抽样复核 |
| `rescue` | `剩余 ≤ 安全缓冲`（`max(90s, 预计还需 × 0.15)`）；或剩余已归零 | 只保「不空白」：所有未答题立即给最优解填满，存疑题标注后补 |

`预计还需 = 未答题数 × 每题均耗 × 1.4`，每题均耗来自 `budget` 记录的累计进度，首屏无样本时按每屏默认 45 秒估。安全系数与缓冲是为了给「平台自动交卷前的网络 / 弹层 / 确认」留余量。

**模式只会往更紧的方向切**：一旦 `timed` 不再回到 `full`，避免中途又把慢流程捡回来。

## 五、降级顺序（时间不够时按这个顺序砍）

先砍质量关卡，**最后才砍题**：

| 顺序 | 砍掉什么 | 保留什么 |
| --- | --- | --- |
| 1 | 双答案交叉（独立重做第二轮） | 一轮作答 + 答案守恒校验 |
| 2 | 文本题量化后的多轮打磨（最多 3 轮 → 只写 1 版） | 术语、数字、结论不动 |
| 3 | 填空题「整篇收齐 + 两轮反向交叉」 | 整篇收齐（这个不能砍，否则编号必错）；只做一轮 |
| 4 | 逐屏 `shot` 复核 | 每 3–4 屏抽样复核 1 次，且 `fill` 后至少看 1 张 |
| 5 | 存疑题的反复推敲 | 先给最优解填入，题号记入存疑清单，有余力再回头 |

**答题优先级**：客观题 > 填空题 > 短文本 > 长作文。听力 / 口语在 `timed` / `rescue` 下直接跳过或按用户给的答案填，理由见下一节。

## 六、限时下禁用的链路

- **禁止启动听力回环录制 + 云端转写**：整卷实测 41 分钟、单次播放不可回放，任何限时卷都装不下。限时周测里听力题按用户给的答案填，或跳过并在回报中标明。
- **口语题不代录**：准备 / 作答各有独立倒计时，且必须本人录音。
- **不要为了赶时间跳过 `guard`**：红线检查只是一次文本匹配，几乎不耗时；限时周测不带监考特征，正常放行。
- **不要用 `next` 翻页**：实测不响应，白费一轮；用答题卡跳题。

## 七、保底填满与存疑后补

用户已授权「先保底填满、存疑题后补」。执行口径：

1. 进入 `rescue` 后，**先把所有未答题按当前最优判断填入**，宁可存疑也不留空。空题在自动交卷后是确定的 0 分，存疑题至少有得分期望。
2. 每填一题，把题号、选择、一句话理由记进存疑清单；不要因为标了存疑就不填。
3. 存疑清单在回报里**单独列出来**，写清两种判断与理由，交用户定夺；有余力再回头重判。
4. 文本题即使来不及打磨，也要写一版完整答案落进输入框，不要留空。
5. **不得用「差不多」补满填空题的守恒检查**：答案守恒是机械校验，几乎不耗时，任何模式都保留。

## 八、交卷：归零自动，但主动交卷仍需用户同意

- 平台归零自动交卷是**平台行为**，不规避、不干预、不修改页面计时、不改系统时间。
- `budget` 判定 `rescue` 且剩余逼近 0 时输出 `[ACTION_REQUIRED]`，助手必须立刻告知用户：剩余多少、还有几题没填、平台即将自动交卷。
- `submit` 在检测到剩余 ≤ 120 秒时也会打印同样提示。**是否现在主动点交卷（`--yes`）必须由用户明确同意**；用户不答就什么都不点，让平台按规则自动交卷。
- 交卷后照常走 `postsubmit` 报告与录音删除询问流程。

## 九、边界（与 SKILL.md 安全边界一致）

- 只用于本人已获授权的自主训练、课程周测与开放性测验；出现监考 / 考试码 / 人脸识别 / 抓拍时 `guard` 拦截并停止。
- **不冻结、不篡改、不伪造页面倒计时，不绕过自动交卷，不改系统时间。** 本文件所有策略都只是「在规则允许的时间内把操作排得更快」，不触碰任何平台机制。
- 来不及就如实说，不猜分数、不谎报完成度。

## 十、回报口径

在 SKILL.md「输出要求」之外，限时卷还要报：

1. 计时形态（倒计时 / 正向计时）与开局剩余；
2. 本轮结束时剩余时间、已用时间、每题均耗；
3. 实际跑的模式（`full` / `timed` / `rescue`）、中途切过几次档、砍了哪些关卡；
4. 是否有平台自动交卷风险、是否主动交卷；
5. 存疑清单（保底填入的题号 + 两种判断），便于用户交卷后复核。
