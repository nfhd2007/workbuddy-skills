# 页面结构观察记录（双站点）

## 站点 A：hike-teaching-center.polymas.com（AI智慧课程中心）

标题：AI教学中心 / AI智慧课程中心

- 存在浏览器检测。非现代浏览器访问只返回「当前浏览器暂不支持，请使用最新版本浏览器」+ Chrome 下载链接，拿不到课程 DOM。
- 平台归属：页面标题「智慧树·AI教学中心」，登录页文案「对于学校机构的用户，我们推荐使用机构登录或者工号登录」。**实际是智慧树（zhihuishu）体系的教学中心**。
- 登录方式（2026-11-21 观察）：通过机构登录（新）/ 通过微信登录 / OR / 免密登录（默认激活，手机号 + 短信验证码）/ 账号登录 / 学号登录 / 工号登录。底部需勾选同意《智慧树用户协议》《隐私政策》《大白明模型服务协议》，「登录」按钮才从置灰变为可用。
- 未登录时可见 DOM 只有 7 个可交互节点（四个登录 tab、区号按钮、手机号输入框、验证码输入框）——**登录页 DOM 极简，课程页结构必须登录后才可见**。
- 已登录判定：出现「AI智慧课程中心」「我学的课」「+加入课程」等文案。
- **课程卡片不在可见 DOM 快照里**：课程中心页快照只返回 3 个可交互节点（学期下拉 combobox、搜索输入框、「加入课程」按钮），12 张课程卡片一个都没出现 → **进入课程必须截图 + 坐标点击（`cua_click`），不能指望 `node_id`**。
- **DOM 快照在这个站点基本不可用**：课程中心页 3 个节点、课程主页 1 个空 button、「我的学习」页 0–1 个节点；左侧导航与课程卡片全部不在快照里。
- 用户已登录的 Chrome 窗口与 WorkBuddy 内置浏览器会话不共享，登录态需在受控标签中由用户本人建立一次。
- 单页应用，直接 HTTP 抓取无法获得课程结构。

## 站点 B：wisdom-mooc.zhihuishu.com（智慧树 MOOC 学习页）

URL 形态：`https://wisdom-mooc.zhihuishu.com/study/index?recruitAndCourseId=<id>`
实例：`...4e5b5c5b455b4859454a585859415a475d` → 海南大学「习近平新时代中国特色社会主义思想概论」

- **DOM 快照可用**（20+ 节点）：章节点 `role="button"` 文案如「第零章: 绪论」「第一章: 新时代坚持和发展中国特色社会主义」；小节为编号 `div`（`0.1`）+ 标题 `div`（问句式，如「习近平新时代中国特色社会主义思想是在怎样的时代背景下创立的？」）；每章末尾有 `测试` span。
- 章节点可 `dom_cua_click` 展开/折叠；**未展开章节的小节不在快照里**，统计前需逐章展开。
- 三栏布局：左侧章节树 / 中间视频封面 +「AI课程导览」摘要列表（含时间段 `00:00:17 - 00:00:57`）/ 右侧「AI学伴」（Hi，<姓名>、AI指令、知识点讲解、视频解读、AI画板、知识图谱、对话输入框）。
- 视频封面态：卡通熊插图 + 免责文字「本视频中如使用图片、视频等资料来自网络，仅供教学使用」+ 右侧圆形「举手」按钮（**不是播放键**）。播放控件未在封面态暴露，**未观察到「下一节」按钮**。
- **完成标记只在截图可见**：小节前有紫色/蓝色圆形 ✓ 勾选；DOM 快照不含完成状态。第零章 0.1–0.3、第一章 1.1–1.3、第二章 2.1–2.3 均已勾选，用户确认「都看完了」。
- 「测试」节点属于考核类，命中即停止（符合技能硬性边界）。
- 顶部：`< 海南大学`、右上「菜单」、用户姓名。

## 通用工具层经验（两个站点都适用）

- 受控标签可能在登录、reload、claim 其他标签后被关闭或重置（2026-11-21 实测多次）：重新 `user_open_tabs` + `tabs_claim` 即可恢复，登录态仍保留。**受控状态会周期性丢失，每次关键动作前先 `tabs_list` 确认**。
- 坐标点击首次可能不生效（实测 2 次），重试一次、或把「点击 + 截图」放进同一个 `cua_execute` 动作序列更稳。
- 截图偶尔报 `provider invocation timed out`（曾连续 3 次），`tab_reload` 后恢复；期间标题与 URL 仍可读，页面没崩。
- URL 路由滞后：点击课程卡片后立刻读 URL 仍是课程中心，稍后才变成 `/agent-course-full/<courseId>/stu/course-home`；**判定是否进入课程以截图为准**。

> 状态：**部分填充**。登录页、课程中心、课程主页、我的学习页、智慧树章节树与完成标记已记录；**播放中状态、一节结束判定、下一节按钮、音量控件、弹窗、后台播放表现仍未观察**——所选课程全部小节已完成，且不应为了试跑去重播已完成视频，故保留 TODO。技能在这些项上按保守策略（`UNKNOWN` 不点击）运行。

## 来自 OCS 源码的候选线索（未验证）

调研 `ocsjs/ocsjs` 时看到的选择器与文案，仅供将来有未完成视频课程时指导「看什么」，**不能当作本技能已确认事实**，也不能直接写成状态判定依据：

- 完成标记候选：`.finish-icon` / `.isFinish` / `.time_icofinish` / `label.success` / `i.select` / 进度 `100%` / `必学 x/y`。本技能实跑确认的是**截图上的圆形 ✓ 勾选**，二者是否对应未验证。
- 当前项候选：`.current` / `.current_play` / `.activeNode` / `.active-file` / `.is-current`；任务列表候选：`.chapter-content .chapter-item` / `.clearfix.video` / `.resources-item` / `.source-icon` / `.el-tree-node`。
- `Hike` 与 `HikeV2` 并存，说明 polymas 侧至少有新旧两版 DOM，认不出结构时按 `UNKNOWN` 停下。
- 本技能无 JS 执行能力，上述 CSS 选择器**无法直接使用**；只能靠可见 DOM 快照与截图人工判读。完整调研与边界对照见 `references/ocs-reference.md`。

## 注意事项

- 只记录界面上可见的文字与节点特征，不要记录 Cookie、Token、账号等敏感值。
- 严格区分「本技能实跑确认」与「第三方源码线索」：只有前者能进入「已确认」栏并同步到 SKILL.md 的分类表。
- 每次修订后同步更新 SKILL.md 的「状态判定」与「第 3 步」分类表。
- 若平台改版导致文案变化，优先停下报告，不要按旧文案盲点。
- 答题界面的 DOM 结构尚未实跑确认，`answer-assist.md` 里的判定只依赖可见文案，不依赖选择器。
- 自动填写依赖最新一次快照的 `node_id` / 坐标，界面变化后必须重新观察；按钮文案均为待验证候选。
