# 知到/智慧树掌握度助手

> 技能名（中文）：`知到/智慧树掌握度助手`；目录名 / 技术标识：`zhihuishu-mastery-assistant`。沿用 WorkBuddy 官方技能惯例（如内置「发布为应用」技能为 `name: 发布为应用` + 英文目录 `sites`）：`name` 为界面显示的中文名，目录名保持 hyphen-case 以便路径与引用稳定。平台名称「知到」与「智慧树」指同一体系，本技能统一称「智慧树」。

## 总览

把「掌握度分析」页里所有**未满知识点**逐个拉满：在用户本人已登录的浏览器会话中，走通导航链路，扫描掌握度热力图，对每个未满知识点打开平台自带的自测题，逐题读图判题 → 点选 → 提交 → 校验结果页 → 返回 → 记录台账，直到热力图里不再有未满格子。

实测结论（2026-11-27，海南大学「习近平新时代中国特色社会主义思想概论」共享课）：

- 掌握度分析页路径：`https://wisdom-mooc.zhihuishu.com/study/analysis?recruitAndCourseId=<id>`。
- 热力图按「知识模块 N」分组，每模块 4 个圆角方格，每格一个知识点。
- **未满格子**点开浮层显示「掌握度：X%」+ 紫色「去提升」；**蓝色免考格子**点开显示「该知识点为免考知识点，不计入掌握度」，没有去提升，必须跳过。
- 点「去提升」打开该知识点的**自测题浮层**：顶部知识点名 +「测试题目」标签、右上「提交」、右侧「答题卡」、底部「上一题 / 下一题」；实测一套 5 题（1 道多选 + 4 道单选），题量以当次答题卡为准。
- 全对提交后进入结果页：大圆「100% 掌握度」、总题数、已答对、「查看作答记录与解析」、「知识点路径」与「知识点资源推荐」。
- 返回结果页后分析页**自动刷新且服务端持久化**：实测平均掌握度 0% → 2.7%、遗漏点 37 → 36、能力达成度 0% → 1.7%、饼图「较好」0.0% → 1.7%，reload 后仍保持。
- 浏览器实例实测：`browser_id=1` 为内置 IAB（`type: desktop`，**无** `user_tabs`），`browser_id=2` 为 **WorkBuddy Edge 扩展**（`type: extension` / `family: edge` / 扩展版本 0.2.8 / 含 `user_tabs`）。全链路实跑在 2 号实例上完成。

**为什么不用 DOM 快照**：实测 `dom_cua_get_visible_dom` 在首页有 34 个节点，但「我的学堂」之后的课程列表、菜单面板、掌握度分析页、热力图格子、格子浮层、自测题浮层、结果页**全部只有 0–1 个节点**。因此全链路以「截图 + 坐标点击」为主，DOM 快照只用来确认首页入口与登录态。所有坐标必须**从当前这张截图现量**，不硬编码。

**实况运行的截图会落盘，收尾要清理**：每次 `tab_screenshot` 会被平台缓存到 `~/.workbuddy/blobs/`，一次完整实况运行可产生几十到上百张。仅 `channel=live/assisted` 且确实产生过截图时，在首次截图前建立运行清单、收尾自动删除**本次运行新增**的截图缓存，只按白名单逐文件删除，不整目录清空、不删台账、不碰用户文件；`channel=readonly/offline` 无截图产物，跳过清理且不必汇报（详见「截图缓存与清理策略」与工作流程第 9 步）。**清理不优先于对用户提问的回答。**

## 交付优先原则与通道分级（先于一切环境判断）

**核心原则：阶段 P 是「选路」，不是「闸门」。用户问什么，就先交付什么；浏览器实例、已登录会话、桌面动作层、插件安装都只是「能否实况采集」的条件，绝不是「能否回答」的条件。**

一次运行先确定两个相互独立的变量：

| 变量 | 取值 | 含义 |
|---|---|---|
| `channel` | `live` / `assisted` / `readonly` / `offline` | 本次能用什么采集通道（由阶段 P 探测） |
| `delivery` | `answer` / `drill` / `live-run` | 本次要交什么：只答页面信息 / 逐题演练清单 / 真实拉满（由**用户本次提问**决定） |

`channel=offline` 时 `delivery` 仍可以是 `drill` 或 `answer`，**不得因为采集通道不可用就把交付降级成「一份阶段 P 环境自检报告」**。

| 通道 | 触发条件 | 可做 | 不可做 |
|---|---|---|---|
| **A · 实况（Edge 扩展）** | `browsers_list` / `user_open_tabs` / `tabs_claim` / `tab_screenshot` / `cua_click` 可加载，且有 `type=extension` + `family=edge` + `user_tabs` 的已登录实例 | 真实导航、截图读热力图、逐题点选、提交、写台账 | — |
| **B · 桌面接管** | A 不可用但 `computer-use` / `desktop-control` 可用 | 同 A（占用真实鼠标键盘，需先提示用户） | 不并发操作 |
| **C · 只读补齐** | A/B 不可用，但 `WebFetch` / `WebSearch` / 本地台账 `Read` / 用户贴出的截图与题面 / `knowledge_search` / `conversation_search` 可用 | 读公开页面信息、核对权威资料、复用历史台账与实跑记录、基于用户材料推演 | 不登录、不写入平台、不代答计分考核 |
| **D · 离线演练** | 上述通道全不满足（典型：沙箱里 `mcp__browser__*` schema 加载不到、连接器列表为空、桌面层未安装、插件装不了） | **直接产出可确认交付**：页面标题与提示/异常、颜色档位与跳过规则、缺口双口径汇总、逐题演练答案清单、看答案时怎么填 | 不冒充实况采集、不写入平台、不编造「本次实测」数值 |

**四条不可违背的交付纪律**：

1. **不阻断**：任何通道缺失都不得导致「停止、只交阶段 P 结论表」。`route=offline` 是合法的继续路径，不是失败。
2. **按提问范围作答**：用户只问「页面标题 / 有无提示或异常」，就只答这两项；阶段 P 结论、台账路径、截图清单、下一步引导一律不夹带。用户要「逐题答案清单」，就先给逐题答案，不先讲环境。
3. **免确认优先**：用户声明「沙箱模式 / 不需要人工确认 / 直接给答案 / 演练 / 不用问我」时，跳过询问课程、跳过索要提交授权、跳过要求安装扩展与「回复继续」；用上下文里的课程名或明确写出假设，直接产出。提交授权只在 A/B 通道真的要点「提交」写入平台时才需要。
4. **事实标注**：离线交付逐项标明「实测已知（来自技能内 2026-11-27 实跑记录）」/「推断」/「本次未采集」。没采集到就说没采集到，不把历史实测值冒充本次页面数据。

**「不得用 HTTP / 命令行绕过」的准确适用范围**：只禁止**绕过登录态去操作真实平台、写入平台数据、代答计分考核**；不禁止在 C/D 通道用 `WebFetch` / `WebSearch` 查公开页面信息、用 `Read` 读本地台账、基于用户提供的题面做离线推演。沙箱 / 演练环境是这条限制的明确例外，不得据此停工。

**红线分级**：作业考试 / 计分 / 监考 / 人脸 / 验证码 / 自动登录 / 题库接口 / 凭据 / 风控绕过仍是**真红线，零点击停止**；「无插件即阻断、不带病开工」只是 A 通道的选路提示，**不是停工红线**，在沙箱环境不得作为拒绝交付的理由。

## 浏览器通道选择（实况通道 A 的首选，不是交付前提）

以下实例选择规则**只约束 `delivery=live-run` 的实况运行**；`channel=C/D` 时不选实例、不引导安装、不要求登录。真实写入操作仍必须在**用户本人已登录**的会话里完成。

**默认且优先：WorkBuddy Edge 扩展程序**（`browsers_list` 里 `type: "extension"`、`family: "edge"`、名称 `Microsoft Edge`、`capabilities` 含 `user_tabs`）。理由：

- 登录态只存在于用户自己的 Edge 里；内置浏览器 IAB 是独立会话，不共享登录态。
- 只有扩展型实例带 `user_tabs` 能力，才能用 `user_open_tabs` + `tabs_claim` 接管用户已打开的智慧树标签；IAB 没有该能力，只能新建标签，且用户必须重新登录。
- 实测 `browsers_list` 的第一个实例就是 IAB。**绝不能默认取列表里的第一个 `browser_id`**，否则会直接卡在「找不到已登录标签」。

| 优先级 | 实例 | 识别条件 | 何时使用 |
|---|---|---|---|
| **1（默认）** | WorkBuddy Edge 扩展 | `type=extension` 且 `family=edge`（或 `name` 含 `Microsoft Edge`）且 `capabilities` 含 `user_tabs` | 无条件首选 |
| 2 | 其他扩展（Chrome / QQ 浏览器） | `type=extension` 且含 `user_tabs` | 用户明确指定，或 Edge 扩展确实不可用 |
| 3（降级） | 内置 IAB | `type=desktop` / `name=WorkBuddy Browser` / 无 `user_tabs` | 仅当扩展全部不可用且用户明确同意「在 IAB 里本人重新登录」；`route=degraded` |

**执行纪律**：

1. 阶段 P 先 `browsers_list`，按上表挑出 Edge 扩展实例，再用 `browser_info(browser_id)` 复核 `user_tabs` 与标签模式；**不要按序号取第一个**。
2. 全程复用同一个 `browser_id`，不跨实例混用 `tab_id`；遇 `stale_tab` / `browser_not_found` / `extension_disconnected` / `host_restarted`，从 `browsers_list` 重新确认同一个 Edge 实例并重新 `tabs_claim`。
3. **Edge 扩展未连接时的引导**（不代装、不点安装器、不改系统设置；**仅当用户明确要实况运行、环境可安装、且未声明沙箱 / 免确认时**）：请用户打开 WorkBuddy「设置 > 智能体 > 浏览器操控」，在 Microsoft Edge 一栏点「前往安装」，安装并启用 **WorkBuddy Edge 扩展程序**，保持 Edge 打开且扩展为启用态，然后回复「继续」重跑阶段 P。若 Browser Use 插件未启用，先引导启用 `workbuddy-browser-use`；内置浏览器不可用时**不要求**用户安装外部扩展。**沙箱 / 工具 schema 加载不到 / 用户只要答案清单时不做此引导**，直接按「交付优先原则」落 C/D 通道交付。
4. 降级到 IAB 时必须在汇报里写明后果：需要用户本人在 IAB 重新登录、无法接管已打开的分析页标签、视口可能变化导致坐标基准全部要重新现量。
5. 收尾**保留受控标签**便于断点续跑；不调用关闭类工具。官方 Browser Use 规范建议收尾调用 `tabs_finalize`，本技能如确需调用，必须带保留语义（`keep`），不得结束用户原有标签。

**与 WorkBuddy Browser Use 官方通用原则的偏差（有实测依据，不必纠正）**：

- 官方口径「未指定浏览器时优先使用内置浏览器」有明确例外——「需要其中的登录状态时，选择对应的扩展浏览器」。本技能恒属于该例外，且用户已明确指定偏好，因此覆盖为「默认 Edge 扩展」。
- 官方口径「优先读 DOM、用 DOM 完成点击」在本链路不成立：实测除首页外 DOM 快照全部只有 0–1 个节点。因此本技能以「截图 + 坐标点击」为主，DOM 仅用于首页入口与登录态确认。加载官方 browser-use 技能后不要因这条通用原则改回 DOM 优先。

## 安全边界（先读，不可逾越；按真红线 / 选路提示分级）

**适用范围说明**：下列红线约束的是**真实页面操作与平台写入**。只读采集、历史台账复用、基于用户提供题面的离线推演与逐题演练答案清单**不属于红线触发场景**；在沙箱 / 演练环境里，不得用「环境不具备」冒充红线导致停工。

- **只做本人已获授权的自主训练与课程自检**。本技能实况操作的是「掌握度分析 → 热力图 → 去提升」链路里的平台自带自测题，不是作业、测验、考试。
- **真红线（零点击停止整个循环、报告所见内容）**：真实页面里出现菜单「作业考试」入口、章节树「测试」节点、「计分 / 计入平时分 / 计入成绩 / 限时 / 仅一次提交机会 / 考试码 / 监考 / 人脸识别 / 摄像头抽检 / 屏幕抓拍 / 切屏监测 / 验证码」。判不准是否计分一律按停止处理。
- **不调用题库 / 搜题接口 / 答案 API**，不读取页面隐藏字段、源码里的答案或网络请求；答案只来自模型推理与公开资料核对。演练答案清单同样不查题库，只依据用户提供的题面与技能内已标注的实跑校准样例。
- **不代输账号密码、不处理验证码、不自动重登**；登录态失效只提示用户本人重新登录。
- **提交会写入平台数据且不可撤销**：授权要求**仅适用于 A/B 实况通道实际点「提交」之前**——在阶段 0 明确告知一次「将自动作答并提交自测题以提升掌握度」，用户确认后才批量执行。用户声明沙箱 / 免人工确认 / 演练，或要求「只看答案不提交」时走 dry-run：完成读题与点选、给出逐题答案清单，停在提交前交还用户，**不索要授权、不产生任何平台写入**。
- **不伪造学习事实**：不篡改心跳、不伪造观看时长、不绕过任何风控或验证、不多账号批量操作、不并发开多个课程会话。
- **不关闭用户正在使用的窗口或标签**；受控标签在收尾时保留。
- **「不得绕过」的边界**：禁止绕过登录态去操作真实平台、写入数据或代答计分考核；**不禁止** C/D 通道用 `WebFetch` / `WebSearch` 查公开页面信息、用 `Read` 读本地台账、或基于用户贴出的题面做离线推演。
- **截图清理只针对本次运行产物**：仅 `channel=live/assisted` 且确实产生过截图时执行；只删 `~/.workbuddy/blobs` 白名单目录内、本次运行起始时间之后新增的图片，逐文件 `os.remove`；禁止 `rmtree` / 通配符批量删除 / 递归清空缓存目录，禁止删除台账 `.json`、清单之外的任何文件，禁止扫描用户剪贴板图片（除非截图工具显式返回了该路径）。`scripts/cleanup_screenshots.py` 是唯一允许的清理入口。`channel=readonly/offline` 无截图产物，跳过清理，不写进汇报。
- **「无插件即阻断、不带病开工」不是红线**：它只是 A 通道的选路提示。沙箱无法安装插件、工具 schema 加载不到时，按「交付优先原则」落 C/D 通道继续交付，不得据此停工或把决策权推回用户。
- 用户随时说「停」即立即停止并交还控制权；**先回答用户已问的问题**，清理只是可选补充。

## 阶段 P · 通道探测与交付模式判定（环境自检，选路不是闸门）

**阶段 P 只回答「本次能走哪条通道」，不回答「本次能不能交付」。任何探测结果都不得阻断交付：工具加载不到、连接器列表为空、没有已登录实例、桌面层未安装、插件无法安装，一律落到 `channel=C/D` 继续按用户提问产出。** 不要假设浏览器工具一定可用，不要假设用户已登录，不要默认拿第一个浏览器实例；但也**不要因为探测失败就停止、索要课程、索要授权或要求用户装好插件后回复「继续」**。

先读用户指令定 `delivery`：

- 问页面标题 / 提示异常 / 口径 → `delivery=answer`
- 要逐题答案清单 / 演练 / 沙箱 / 免确认 / 说明怎么填 → `delivery=drill`
- 要真实把掌握度拉满、且 A/B 通道可用 → `delivery=live-run`

再做一次轻量探测（**每项只探测一次，加载不到就直接记「不可用」，不反复重试、不追问用户**）：

| 层 | 探测项 | 可用 → | 不可用 → |
|---|---|---|---|
| **实况层** | `mcp__browser__browsers_list` / `browser_info` schema 可加载、存在 `type=extension` + `family=edge` + `user_tabs` 的已登录实例、`user_open_tabs` / `tabs_claim` / `tab_screenshot` / `cua_click` 在位 | `channel=live`（A） | 转下一层，**不阻塞** |
| **桌面层** | `computer-use` / `desktop-control` 可加载 | `channel=assisted`（B） | 转下一层，**不阻塞** |
| **只读层** | `WebFetch` / `WebSearch` / `knowledge_search` / `conversation_search` / 本地台账 `Read` / 用户贴出的截图与题面 | `channel=readonly`（C） | 转下一层 |
| **离线层** | 无条件（技能自带 `references/site-map.md` / `references/offline.md` 的实测记录始终可读） | `channel=offline`（D） | — |

**决策表**：

| `channel` | `route` | 下一步 |
|---|---|---|
| `live` | `direct` | 条件齐备且走 Edge 扩展优先通道 → 进工作流程第 0 步做实况运行 |
| `live` / `assisted` | `degraded` | 必需能力有缺口或已降级到 IAB / 其他扩展 → 按降级口径继续，汇报里写明影响 |
| `live` | `scene` | 只差用户本人登录 → 说明「准备现场」；**同时仍按 `delivery` 交付能离线回答的部分**，不得只交一份登录引导 |
| `readonly` / `offline` | `offline` | **不停止、不索要课程、不索要提交授权、不要求安装扩展、不要求回复「继续」** → 直接进工作流程「0.5 离线演练交付」小节，按用户提问范围产出 |
| 任意 | `redline` | 仅当真实页面出现作业考试 / 计分 / 监考 / 人脸 / 验证码 → 零点击停止并报告所见内容 |

**插件与安装是可选动作，不是前置条件**：`list_installed_plugins` / `search_plugins` / `suggest_plugin_install` / `search_and_install_skills` 只在 A/B 通道差一步就能就绪、且用户未声明沙箱 / 免确认时使用一次；探测到「当前环境无法安装」就直接落 `channel=offline`，不要让用户去装、不要等用户回复。

**汇报阶段 P 的时机与范围**：仅在 `delivery=live-run`、或用户明确问「环境体检 / 通道情况」时，才输出阶段 P 结论（实例名称 / 类型 / `browser_id`、是否 Edge 扩展优先通道、台账路径、`route` 与降级口径、`route=scene` 时说明「只差您本人登录」）。其余情况**不主动汇报阶段 P**；用户只问页面信息或要答案清单时，阶段 P 结论、自检表、截图清单一律不放进回复。

**截图清单只属于 A/B 通道**：`cleanup_screenshots.py begin` 仅在 `channel=live/assisted` 且即将产生截图时执行；`channel=readonly/offline` 本次没有截图产物，跳过 begin / finish，也不必向用户汇报清理结果。C/D 通道的等价收尾检查是 `Glob` 一次 `~/.workbuddy/blobs` 确认本次没有新增图片，无新增即可结束。详见工作流程第 9 步。

## 前置条件（按交付模式分别判定）

**离线交付（`delivery=answer/drill`，`channel=C/D`）**：

1. 已读 `references/offline.md`（离线演练交付手册）与 `references/site-map.md`（页面标题、颜色语义、实测基线、实测样题）。
2. 已按「交付优先原则」标注每项结论的来源：实测已知 / 推断 / 本次未采集。
3. **不需要**浏览器工具、已登录会话、插件、桌面动作层、课程确认、提交授权、截图清单。用户声明沙箱 / 免确认时，上述项一律不询问、不索要。

**实况运行（`delivery=live-run`，`channel=live/assisted`）**：

1. 阶段 P `route=direct/degraded`，且已按「浏览器通道选择」锁定 Edge 扩展实例的 `browser_id`（`browser_info` 复核 `user_tabs`）。
2. 用户本人已在 **WorkBuddy Edge 扩展程序接管的 Microsoft Edge**（`type=extension` / `user_tabs`）中登录 `https://www.zhihuishu.com/`，首页右上能看到用户名（实测为用户名，姓名已脱敏）。降级到内置 IAB（不共享登录态）时须用户明确同意并在 IAB 内重新登录。
3. 浏览器窗口可见、缩放 100%、未被完全遮挡；不要最小化。
4. 用户已指定课程；**且仅在实际点「提交」之前**需要一次会话级提交授权。用户已声明沙箱 / 免确认 / 演练时，不询问、不索要授权，也不执行真实提交。
5. 已阅读 `references/site-map.md`（页面地图、颜色语义、坐标基准）与 `references/tooling.md`（工具速查、实例识别与踩坑）；进入答题循环前已阅读 `references/answering.md`（判题、纠错、提交纪律）。
6. 即将产生截图时已执行 `cleanup_screenshots.py begin --file <清单>` 并记下**本次截图清单路径**；收尾按第 9 步 `finish --file <清单>`，但**清理不优先于对用户问题的回答**。

## 工作流程

> 本节分两条支路：`delivery=live-run` 走第 1–9 步实况循环；`delivery=answer/drill`（或任意 `channel=readonly/offline`）**直接跳到「0.5 离线演练交付」小节**，第 1–8 步不适用，也不得因为跳过了实况步骤就交空壳报告。
>
> 实况支路的所有坐标均指**当前截图内 CSS 像素坐标**（截图左上角为 0,0）；分辨率与实测 1699×888 基准不同时，一律重新截图现量坐标，不按比例硬套。
>
> 实况支路会产生大量截图（每屏扫描、每道题、每次点选复核都要截一张）。**每次 `tab_screenshot` / `cua_execute` 内嵌 screenshot 之后，若工具结果里给出了截图落盘路径或 `file://` URI，就用 `cleanup_screenshots.py add --path ...` 登记**；工具不返回路径也没关系，`finish` 会按「起始时间之后新增」自动兜底识别。收尾清理见第 9 步；离线支路无截图，跳过。

### 0. 确定交付模式（不要一上来就问课程 / 要授权）

1. 先读用户指令：出现「沙箱 / 演练 / dry-run / 不需要确认 / 不用问我 / 直接给答案 / 只看答案 / 说明怎么填」→ `delivery=drill`，**跳过询问课程与提交授权**，直接进「0.5 离线演练交付」；用上下文里的课程名，没有就明确写「以下以实测共享课为例，课程名按实际替换」。
2. 用户只问页面标题 / 提示异常 / 口径 → `delivery=answer`，进「静态页面信息速查」与「0.5 离线演练交付」，不询问、不引导安装、不汇报阶段 P。
3. 用户要真实拉满且 `channel=live/assisted` → `delivery=live-run`：若用户已给出课程名直接采用；否则用 `AskUserQuestion` 列出从「我的学堂」课程列表截图读到的课程名（AI 智课与共享课分开列），让用户选；列表读不全时请用户直接输入课程名。
4. **同名课程**以课程名为准、辅以学期或点击后的课程主页标题区分；不要用教师名匹配（实测教师名可能是 URL 编码乱码）。
5. **提交授权只在实况写入前**：`delivery=live-run` 且即将点「提交」时，明确告知一次「每个未满知识点会打开平台自测题，我将自动作答并点『提交』写入掌握度；提交不可撤销。是否允许？」；用户选「只演练不提交」→ 转 dry-run，走到提交前停止并输出答案清单。`delivery=drill` / 沙箱 / 免确认时不索要授权，因为不产生任何平台写入。
6. 若用户表示「已经全部拉满了」，先读一次基本信息（遗漏点数量 / 薄弱点数量）；确为 0 就直接输出台账汇总并停止，不要为了试跑去重做已完成知识点。

### 0.5 离线演练交付（`channel=readonly/offline`，或 `delivery=answer/drill`）

**这是本技能的一等交付路径，不是「降级后的安慰奖」。** 只要浏览器通道不可用（典型：沙箱里 `browsers_list` / `user_open_tabs` / `tabs_claim` / `cua_click` schema 都取不到、连接器列表为空、方案 B 桌面层未安装、插件装不了），就在这里把用户要的东西一次性交齐，**不输出阶段 P 结论表、不索要课程、不索要授权、不要求回复「继续」**。

按 `delivery` 取用 `references/offline.md` 的对应模板：

| 用户要什么 | 必须交付什么 | 来源 |
|---|---|---|
| 页面标题、有无提示或异常 | 逐页标题 + 已知提示 / 异常清单 + 「本次未实况采集」说明 | 「静态页面信息速查」+ `offline.md` |
| 逐格读颜色档位 | 5 档颜色判据表（绿较好 100-80 / 黄一般 80-60 / 粉薄弱 60-0 / 白框遗漏 0 / 蓝免考） | `site-map.md` 图例表 |
| 标出可跳过与待补格子 | 跳过 = 绿格 + 蓝免考格（附免考浮层文案）；待补 = 白 / 黄 / 粉，附「模块 N + 列 C」编号法与实测基线（60 个知识点 / 遗漏 37 / 薄弱 0 / 免考 23） | `site-map.md` 基本信息卡 |
| 汇总缺口 | 双口径：① 格子级 `pending` 清单（模块 / 列 / 标题 / 初始掌握度 / 状态）；② 全局交叉校验「遗漏点数量 + 薄弱点数量」；离线时给出**可填模板 + 实测基线样例**，注明哪些数值需实况采集 | `offline.md` |
| 按当前题目逐题作答、标注多选与存疑 | **逐题答案清单**：题号 / 题型（单选或多选）/ 所填选项 / 一句话理由 / 置信度 / 存疑标记；并单独说明「看答案时怎么填」（多选逐个点、答题卡跳题、提交前检查所有题号深紫） | `answering.md` + `offline.md` 示范清单 |
| 看答案时怎么填 | 逐题填答映射表：第 N 题 → 点 A–D 哪一行 / 多选点哪几个；答题卡点题号回查；dry-run 停在提交前 | `offline.md` |

**题面来源优先级**：① 用户本次贴出的题干 / 截图 / 答案清单；② 台账与历史实跑记录（`Read` 台账 JSON、`conversation_search` / `knowledge_search`）；③ 技能内 `site-map.md`「实测样题」5 题（**明确标注为 2026-11-27 实跑校准样例，不是题库、不保证与当前题目一致**），可作为「逐题演练答案清单」的即用示范；④ 若三者都没有，就交付带占位符的**演练答卷模板**并说明如何按当前题目逐题填，**绝不空手交一份环境报告**。

**事实辨别纪律**：离线答案一律写「演练 / 示范 / 需按当前题目核对」，不得写成「本次页面实测」；没有采到的热力图数值明确写「本次未采集」，用 `site-map.md` 的历史实测值时标注「历史实测基线」。红线在演练中同样适用：不调题库接口、不读隐藏答案、不代答计分考核；但**演练本身不触发停工**。

### 1. 进入官网，点「我的学堂」（用户流程第 2–3 步）

1. `browsers_list` 取实例列表，按「浏览器通道选择」挑 **Edge 扩展**实例的 `browser_id`（`type=extension` + `family=edge` + `user_tabs`），`browser_info` 复核能力；**不要取列表第一个（实测为内置 IAB）**。后续所有工具调用固定复用这个 `browser_id`。
2. 在该实例上 `user_open_tabs` 找已登录的智慧树标签，`tabs_claim` 接管；没有则 `tabs_new` + `tab_goto` 打开 `https://www.zhihuishu.com/`。
3. `tab_screenshot` + `dom_cua_get_visible_dom` 确认已登录（右上出现用户名）。首页 DOM 里「我的学堂」是明确链接（`href=https://onlineweb.zhihuishu.com`），**优先用 `dom_cua_click` 点它的 `node_id`**。
4. 点击后若 `tab_url` 落在 `onlineweb.zhihuishu.com` 或 `hike-teaching-center.polymas.com` 都属于正常（平台会把「我的学堂」路由到新版 AI 智慧课程中心）。截图超时或跳到 `chooseOrgan` 时先 `tab_reload` 一次再截图，实测 reload 后即为「AI智慧课程中心 / 我学的课」课程列表。
5. **URL 路由滞后**：以截图出现课程卡片网格为准，不要立刻读 URL 就下结论。
6. 受控状态丢失时，从 `browsers_list` 重新确认**同一个 Edge 实例**再 `tabs_claim`，**不跨实例混用 `tab_id`**。

### 2. 点击相应课程（用户流程第 4 步）

1. 课程卡片**不在 DOM 快照里**（实测只有 6 个节点：学期下拉、搜索框、加入课程、更多和两个空 button）→ 必须截图 + 坐标点击。
2. 在截图里按课程名定位卡片中心（实测 1699×888 下第一行 6 张卡、第二行 6 张卡、第三行 3 张卡，卡宽约 240px、卡高约 210px、横向间距约 20px）。点卡片标题或封面中心均可。
3. **首次点击常不生效**（实测第一次只触发图片懒加载）：重试一次；仍无效则把「点击 + 截图」放进同一个 `cua_execute` 动作序列。
4. 点课程卡片会**打开新标签**（`wisdom-mooc.zhihuishu.com/study/index?recruitAndCourseId=<id>`），不是本标签跳转。用 `user_open_tabs` 找新标签并 `tabs_claim`，记录 `browser_id` / `tab_id` 与 `recruitAndCourseId`。**不要因为没看到跳转就连点多次**，实测连点会开出两个重复标签。
5. 确认学习页已加载：左侧章节树、中间视频区、右侧 AI 学伴、右上「菜单」与用户名。

### 3. 点「菜单」（用户流程第 5 步）

1. 学习页右上「菜单」（田字格图标 + 文字，实测 1699×888 下约 `(1528, 36)`）**不在 DOM 快照里** → 坐标点击。
2. 展开的菜单面板含 12 项，实测第一行：课程学习（当前选中，浅紫底）、知识图谱、**掌握度分析**（奖杯图标，第一行第三个，约 `(1473, 165)`）；其余为成绩分析 / 作业考试 / 课程资料 / 课程问答 / 见面课 / 学前必读 / 客服 / 系统消息 / 课程提醒 / 班级信息 / 退课。
3. 菜单项同样不在 DOM 快照里 → 坐标点击「掌握度分析」。**不要点「作业考试」**（安全边界）。

### 4. 进入掌握度分析（用户流程第 6 步）

1. 点「掌握度分析」会**再开一个新标签**，URL 形如 `https://wisdom-mooc.zhihuishu.com/study/analysis?recruitAndCourseId=<id>`。用 `user_open_tabs` + `tabs_claim` 接管，之后所有操作都在这个标签。
2. 截图读取**基线**并写入台账：知识点总数、平均掌握度、薄弱点数量、**遗漏点数量**、免考数量、能力达成度、饼图各档占比。实测初始：60 / 0% / 0 / 37 / 23 / 0%。
3. 该页 DOM 快照只有 1 个节点（用户名），之后全靠截图。

### 5. 下拉扫描热力图，建立待办台账（用户流程第 7 步）

1. 用 `cua_scroll`（内容区，如 `(850, 600)`，`scroll_y` 约 650）往下滚到「掌握度热力图」；`cua_scroll` 报 `provider invocation timed out` 时改用 `dom_cua_scroll` 或键盘 `PageDown`，再不行 `tab_reload` 后重试。**每次滚动后必须重新截图确认位置**，不盲滚。
2. 图例颜色语义（唯一判据）：

   | 颜色 | 图例 | 处理 |
   |---|---|---|
   | 绿色 | 较好 100-80 | **已满，跳过**（实测全对提交后格子变绿） |
   | 黄色 | 一般 80-60 | 未满，进入第 6 步 |
   | 粉色 | 薄弱 60-0 | 未满，进入第 6 步 |
   | 白框 | 遗漏 0 | 未满，进入第 6 步（实测最常见） |
   | 蓝色 | 免考 | **跳过**：浮层提示「该知识点为免考知识点，不计入掌握度」，无去提升 |

3. 每屏截图现量格子坐标：实测 4 列固定 x（约 377 / 515 / 652 / 790），每模块一行、模块间距约 232px，格子约 118×120px。按「模块序号 + 列序号」给每个未满格子编号，写进台账 `pending`，字段至少含 `module` / `col` / `title` / `initial_pct` / `status`。
4. 需要严格拉到 100% 时，可点开绿格读浮层的「掌握度：X%」；低于 100% 的绿格也纳入 `pending`。默认按平台分档，绿格视为已满。
5. 热力图很长（实测 60 个知识点 / 约 15 个模块），**分段滚动 + 每屏建台账**，不要试图一次记全；用「遗漏点数量」作为全局剩余量交叉校验，防止漏格。

### 6. 逐知识点拉满循环（核心）

对台账里每一个 `pending` 知识点，按固定顺序执行；**每完成一个都要回分析页重新下拉、重新截图、重新量坐标**（实测提交返回后页面会滚回顶部）：

1. **点格子**：按最新截图坐标 `cua_click` 点未满格子 → 浮层出现「知识点标题 / 掌握度：X% / 去提升」。浮层有淡入动画，`cua_execute` 里的截图可能拍到半透明中间态，**再单独 `tab_screenshot` 一次**确认。
   - 若浮层写的是免考提示 → 标记 `skipped_exempt`，跳过。
   - 若浮层没有「去提升」且不是免考 → 归 `UNKNOWN`，不点击，报告。
2. **点「去提升」**：浮层内紫色按钮（实测约 `(634, 434)`）。点击后浮层开始淡出，**不要立刻判定失败**——页面正在加载自测题浮层，等一次截图再确认。实测第一次点后立刻截图看到的是「浮层消失、页面没变」，再截一次才是答题界面。
3. **逐题读图判题**：按 `references/answering.md` 执行。要点：
   - 顶部读知识点名与「测试题目」标签，右侧答题卡读总题数（实测 5）。
   - 逐题截图：题干、题型标签（单选题 / 多选题）、A–D 选项整行、底部「上一题 / 下一题」。
   - 判题用「模型推理 + 公开资料核对」双答案交叉；存疑题标注，不留空。
   - **优先用答题卡点题号跳题**（实测 100% 生效），`下一题` 也可用；不要用旧截图的坐标连点。
   - 选项整行可点（实测点圆圈或行内文字都生效）；多选题要逐个点亮。
   - 每次点选后重新截图复核：选项高亮、答题卡题号变深紫（已作答）。
4. **红线检查**：答题浮层里若出现计分 / 作业 / 考试 / 监考 / 人脸 / 验证码 / 限时等字样，立即停止、零点击、报告，不提交。
5. **提交**：全部题号「已作答」后点右上「提交」（实测约 `(1528, 115)`）。**dry-run 模式在此停下**，输出答案清单交还用户。
   - 提交有异步过程，点一次后若截图仍是题目，再截一次；不要连点「提交」。
6. **校验结果页**：必须实际看图，读「掌握度 X% / 总题数 N / 已答对 M」。
   - `M == N` 且显示 100% → 标记 `done`，记录 `final_pct`。
   - `M < N` → 点「查看作答记录与解析」读正确选项，返回重做该知识点（最多 2 轮）；仍不全对则标记 `partial` 并在汇总里列明，不反复盲刷。
7. **返回 + 复核**：点结果页左上返回箭头（实测约 `(57, 115)`）→ 回到分析页顶部 → 截图读基本信息，确认「遗漏点数量」减少、平均掌握度上升。数据没变 → 标记 `unverified`，停下报告，不重复提交。
8. **写台账**：`scripts/mastery.py record` 记录该知识点结果与本题答案摘要；`summary` 随时可查进度。

### 7. 收尾条件

命中任一即停止循环：

- 热力图里不再有未满格子，且基本信息「遗漏点数量 = 0」「薄弱点数量 = 0」→ `ALL_DONE`。
- 用户要求停止、达到单次上限（默认 30 个知识点 / 60 分钟）、连续 3 个知识点 `UNKNOWN`、连续 2 次提交后数据无变化（疑似风控）、出现红线特征。
- 登录态失效 → `SESSION_EXPIRED`，提示用户本人重新登录，不自动重登。
- Edge 扩展断开且重连失败 → 从 `browsers_list` 重新确认；仍不可用则停止并报告，不切到别的实例继续跑同一批 `tab_id`。

### 8. 断点续跑与直达模式

- 台账默认落在 `<CWD>/.workbuddy/mastery/<课程标识>.json`，`scripts/mastery.py pending` 可列出剩余项。下次运行先读台账，跳过 `done` / `skipped_exempt`。
- 首次走通后把分析页 URL 与浏览器通道记进台账（`mastery.py init --channel "edge-extension"`）。后续同课程可直接 `tab_goto` 到 `https://wisdom-mooc.zhihuishu.com/study/analysis?recruitAndCourseId=<id>`，**跳过第 1–4 步**；但每次仍要重新 `browsers_list` 确认 Edge 扩展实例并 `tabs_claim`（实测受控状态会周期性丢失）。
- 换课程必须清空或新建台账，不要沿用旧 `recruitAndCourseId`；换浏览器通道时所有坐标作废，重新现量。

### 9. 收尾：清理本次截图（仅 A/B 通道；不得挤占对用户问题的回答）

**优先级：先按「输出要求」把用户问的东西答完，再在有余力时做清理；两者不冲突时合并到同一次回复。清理绝不是「汇报之前必须先完成的门槛」，更不允许为了流程完整去跑一个空清单。**

- `channel=live/assisted` 且本次确实产生过截图：按「截图缓存与清理策略」执行 `list` → 合理性闸门 → `finish --file <清单>`（或 `--keep`），并把结果作为**可省略的补充项**放在回复末尾。
- `channel=readonly/offline`：本次没有截图产物 → **跳过 begin / finish，不汇报清理结果**。等价的替代收尾检查是 `Glob` 一次 `~/.workbuddy/blobs` 确认没有本次新增图片；无新增即可结束，不必写进回复。
- 阶段 P `route=offline` / `scene` / 红线停止 / 用户叫停但没产生截图时，同样直接跳过清理。
- 用户随时说「停」→ 立即停止并交还控制权；**先回答用户已问的问题**，再处理截图。

实况支路的清理执行顺序（`<清单>` = `begin` 返回的清单路径）：

1. `python "<SKILL_DIR>/scripts/cleanup_screenshots.py" list --file <清单>` 先只读复核：记下「待删合计」与「时间窗口新增」两个数。
2. **合理性闸门**：把「待删合计」与本次运行实际截图次数对照。若数量明显偏大（例如超过实际截图次数的 2 倍，或 `list` 里出现与掌握度页面明显无关的图片），说明同一时段可能有其它会话图片混进来 → 改用 `finish --file <清单> --keep` 只列不删，在汇报里写明「为避免误删全局缓存，本次截图未自动删除，清单保留在 …」，交还用户决定。
3. 数量合理 → `python "<SKILL_DIR>/scripts/cleanup_screenshots.py" finish --file <清单>`。脚本会先打印待删摘要，再逐文件删除、每 10 个一组校验，成功后自动删除清单文件本身。
4. `finish` 返回「删除 N 个 / 失败 M 个 / 剩余 R 个」。若 `M > 0` 或 `R > 0`，**不要重跑 finish、不要换更大的上限盲删**：保留清单，把失败明细写进汇报，提示用户可稍后用 `list --verbose` 复核。
5. 清理只删截图缓存；**台账 `<CWD>/.workbuddy/mastery/*.json` 与受控标签必须保留**，断点续跑依赖它们。这与「浏览器通道选择」里「收尾保留受控标签」不冲突：一个清理本地图片缓存，一个保留浏览器会话。

## 截图缓存与清理策略

**截图落到哪里（实测）**：`tab_screenshot` / `cua_execute` 内嵌 screenshot 返回的是 MCP 图像内容，WorkBuddy 平台会把它落盘到 `~/.workbuddy/blobs/<2 字符前缀>/<sha>.png`（一次完整运行可产生几十到上百张）。该目录是**全局共享缓存**——其它会话、其它技能的图片也在里面，且文件名是内容哈希，看不出属于哪次运行。

**因此禁止**：整目录删除 / `rm -rf` / `shutil.rmtree` / `del *.png` / 按「最近 N 分钟」清空整个 blobs / 连带删除 `~/.workbuddy/clipboard-images`（里面多为用户自己粘贴的图片）。这些做法会不可逆地破坏用户其它会话的图片与平台缓存索引。

**本技能的做法**：`scripts/cleanup_screenshots.py`（纯标准库、跨平台）用「本次运行清单 + 白名单 + 逐文件删除」把范围收窄到可证明属于本次运行的截图：

| 命令 | 时机 | 作用 |
|---|---|---|
| `cleanup_screenshots.py begin --file <清单> [--json]` | **仅 A/B 实况通道**：首次截图之前 | 记录 `started_epoch`、解析白名单目录（默认仅 `~/.workbuddy/blobs`；路径用 `expanduser("~")` 动态解析，不硬编码用户名 / 盘符）、生成清单；C/D 通道跳过 |
| `cleanup_screenshots.py add --file <清单> --path <路径>` | 每次截图后，仅当工具结果给出路径 | 登记精确落盘路径（支持 `file://` URI）；白名单外的路径会被拒绝 |
| `cleanup_screenshots.py list --file <清单> [--verbose] [--json]` | 实况通道收尾前复核 | 只读 dry-run，列出待删文件，**不删除任何东西** |
| `cleanup_screenshots.py finish --file <清单> [--keep] [--max-delete 500]` | **仅 A/B 实况通道且产生过截图的收尾** | 候选 = 显式登记 ∪ 白名单目录内 `mtime ≥ started_epoch` 的新增图片；逐文件校验后删除，成功后删除清单；C/D 通道不执行 |

**内置安全约束（改脚本时不得放宽）**：

- 只用 `os.remove` 删单个文件，**不删目录、不用通配符、不递归清空**。
- 候选必须通过 `realpath` + `commonpath` 落在白名单目录内，且是普通文件（排除符号链接）、扩展名属于 `.png/.jpg/.jpeg/.webp`；台账 `.json`、清单自身、`.workbuddy/mastery/` 下的文件一律保护。
- 默认**不**扫描 `clipboard-images`；只有 `add --path` 显式登记或 `begin --include-clipboard` 才纳入。
- `--max-delete` 上限默认 500，超限一律拒绝删除并要求人工复核；`--keep` 只列不删；`--keep-manifest` 可保留清单供审计。
- 每 10 个一组删除并校验，任一组失败立即停止、报告剩余数量，不继续盲删。
- `finish` 幂等：清单已标记 finished 或清单文件不存在时直接跳过，不会重复扫描删除。

**已知副作用（要如实告诉用户）**：删除的是本地缓存副本，**不影响平台服务端的掌握度数据与台账**；但历史对话里已渲染的截图缩略图可能因源文件消失而不再显示。用户若要复盘，用 `finish --keep` 保留截图与清单。

## 状态判定（重要）

浏览器工具**不能执行任意 JavaScript**（无 `evaluate` / `execute_script`），也没有 wait 能力。因此：

- 只依据**可见截图**判定：颜色、文案、按钮高亮、答题卡题号色块。DOM 快照在本链路基本为空，不能作为状态来源。
- 「已作答」= 答题卡题号变深紫；「已拉满」= 结果页 100% + 热力图格子变绿 + 基本信息数字变化，三者至少取二。
- 浮层有淡入 / 淡出动画，`cua_execute` 内嵌截图常拍到半透明中间态 → **动作后单独再截一张**再判定。
- 认不出颜色或文案时归 `UNKNOWN`，不动作、计数 +1；不因「看起来像」就猜着点。

## 坐标系与踩坑（实测）

- 实测基准 1699×888 CSS 像素，来自 **WorkBuddy Edge 扩展接管的用户 Edge 窗口**；`cua_click` 用同一套坐标，截图上量到直接点，**不做换算**。换分辨率 / 缩放 / 换浏览器通道后一律重新现量。
- 窗口最大化、贴原点、不被遮挡；窗口移动后全部坐标作废，重新 `shot`。
- 首页「我的学堂」有 DOM 节点，优先 `dom_cua_click`；**之后所有页面都靠坐标**。
- 点课程卡片、点「掌握度分析」都会**开新标签**，必须 `user_open_tabs` → `tabs_claim`；受控状态周期性丢失，每轮动作前 `tabs_list` 确认。
- 首次点击常不生效 → 重试一次或用 `cua_execute` 把「点击 + 截图」合并。
- `tab_screenshot` 偶发 `provider invocation timed out` → `tab_reload` 后恢复，期间标题与 URL 仍可读，页面没崩。
- `cua_scroll` 偶发超时 → 改用 `dom_cua_scroll` / 键盘 `PageDown` / reload 后重试。
- 提交、去提升、返回都有异步加载，**点完先等一次截图再判定**，不要连点。

| `cleanup_screenshots.py finish --file <清单>` | **仅 A/B 实况通道且产生过截图的收尾**：逐文件删除本次运行截图缓存；C/D 通道不执行 |
| `cleanup_screenshots.py finish --file <清单> --keep` | 数量异常时只列不删，交还用户决定 |
| `node "<SKILL_DIR>/scripts/lint.py"` → `python "<SKILL_DIR>/scripts/lint.py"` | 发布前自检（关键词、资源完整性、Edge 扩展优先口径、截图清理口径） |
| `tab_screenshot` / `cua_click` / `cua_execute` / `cua_scroll` / `dom_cua_scroll` | 观察与动作 |
| `tab_goto` / `tab_reload` / `tab_url` / `tabs_claim` | 导航与会话 |

## 输出要求（按提问范围自适应，禁止固定模板）

**总规则：用户问什么就先答什么，答完即止。不输出与本次提问无关的阶段 P 结论、自检表、台账路径、截图清单、下一步引导。用中文回报，不贴原始 JSON 或坐标列表。**

1. **先逐条命中用户的问题**：页面标题 → 给标题；有无提示或异常 → 逐条列提示与异常并判定「正常 / 异常 / 红线」；颜色档位 → 给 5 档表；可跳过 / 待补 → 给分类与编号；缺口 → 给双口径汇总；逐题答案 → 给逐题清单（题号 / 题型 / 选项 / 理由 / 存疑）；看答案怎么填 → 给逐题填答映射。**不得用「环境未就绪」替代其中任何一项，也不得用阶段 P 结论表挤占这些回答。**
2. **简短标注事实来源**：每项标「实测已知（技能内 2026-11-27 实跑记录）/ 推断 / 本次未采集」。离线时不要写「本次页面实测」。
3. **补充项（仅在相关时才附，一律放最后且可省略）**：
   - 用户问环境 / 通道，或 `delivery=live-run` → 阶段 P 结论：`route`、使用的浏览器实例（名称 / 类型 / `browser_id`、是否 Edge 扩展优先通道）、降级口径、台账路径；`route=scene` 时说明「只差您本人登录」，降级到 IAB 时说明「需本人重新登录、不能接管已开标签、坐标需重新现量」。
   - 实况运行才附：课程与基线（知识点总数 / 平均掌握度 / 遗漏点 / 薄弱点 / 免考 / 能力达成度）、本轮成果（`done / partial / skipped_exempt / unverified`、是否 `ALL_DONE`）、答题情况（题量 / 答对数 / 存疑题与理由 / 是否用过「查看作答记录与解析」）、停止原因、下一步续跑方式（直达 URL + 台账 + 同一 Edge 扩展实例）。
   - 实际删过截图才附：**截图清理结果**（本次删除 / 失败 / 剩余数量；`--keep` 时给清单路径与原因；台账与受控标签已保留；「历史对话缩略图可能不再显示、平台数据与台账不受影响」）。
   - dry-run / 未提交 → 明确一句「尚未提交，掌握度未改变」。
4. **语气**：不写「被阻断、无法继续、请安装扩展后回复继续」这类把决策权推回用户的话（除非用户主动问环境且 A 通道差一步即可就绪）。用户已声明沙箱 / 免确认时，直接给结论与答案，不追问。
