# 操作清单（照着做）

> 一次完整运行的顺序清单。所有坐标**从当前截图现量**，本文件里的数字只是 1699×888 基准参考（该基准来自 WorkBuddy Edge 扩展接管的用户 Edge 窗口）。详细页面结构见 `references/site-map.md`，工具参数与实例识别见 `references/tooling.md`，判题规则见 `references/answering.md`。
> **v1.3.1**：清单分「离线交付」与「实况运行」两条支路。浏览器工具加载不到时**直接跳到 F 节**，不做 A–E 的任何动作，也不得交空壳报告。

## 先判交付模式（每次运行第一件事）

- [ ] 用户只问页面标题 / 提示异常 / 口径 → `delivery=answer` → 跳 **F 节**。
- [ ] 用户要逐题演练答案清单 / 沙箱 / 免确认 / 演练 / 说明怎么填 → `delivery=drill` → 跳 **F 节**；**不询问课程、不索要提交授权、不要求安装扩展、不要求回复「继续」**。
- [ ] 用户要真实拉满 → `delivery=live-run` → 从 **A 节**往下走；A 通道不可用时按 `channel=C/D` 跳 F 节，同时说明实况未执行。

## A. 开工前（仅 `delivery=live-run`）

- [ ] 跑阶段 P 选路：工具层探测（**只探测一次，加载不到就记不可用**）→ `browsers_list` → **按 `type=extension` + `family=edge` + `user_tabs` 选 Edge 扩展实例**（`browser_info` 复核）→ `user_open_tabs` → `tabs_claim` → 确认首页已登录 → 台账目录可写。
- [ ] **不要取 `browsers_list` 的第一个 `browser_id`**（实测 1 号是内置 IAB，无 `user_tabs`、不共享登录态）；全程复用选定的那个 `browser_id`。
- [ ] 若列表里没有 Edge 扩展且用户要实跑、环境可安装：引导用户在「设置 > 智能体 > 浏览器操控」找到 Microsoft Edge，点「前往安装」安装并启用 **WorkBuddy Edge 扩展程序**，保持 Edge 打开后重跑阶段 P；只有用户明确同意时才降级到 IAB / 其他扩展。**沙箱 / 免确认 / 无法安装时不做此步**，直接跳 F 节。
- [ ] **仅在 `delivery=live-run` 或用户主动问环境时**汇报 `channel` / `route` / 浏览器实例（名称 / 类型 / `browser_id` / 是否 Edge 扩展优先通道）/ 台账路径 / 降级口径；用户只问页面信息或要答案清单时不汇报这些。
- [ ] 阶段 0 确定模式：用户已给课程名直接采用；**已声明沙箱 / 免确认 / 演练时不询问课程、不索要提交授权**。提交授权只在实况点「提交」之前确认一次；用户选「只演练」则全程 dry-run。
- [ ] 读 `references/site-map.md` / `tooling.md` / `answering.md`。
- [ ] **仅实况通道**：首次截图之前跑 `python "<SKILL_DIR>/scripts/cleanup_screenshots.py" begin --file <清单> --json`，记下返回的清单路径。C/D 通道跳过 begin / finish。
- [ ] 之后每次截图，若工具结果给出落盘路径或 `file://` URI，用 `cleanup_screenshots.py add --file <清单> --path <路径>` 登记（不给路径也没关系，finish 会按起始时间兜底）。

## B. 导航链路（用户流程 2–6）

- [ ] 在**选定的 Edge 扩展实例**上打开 `https://www.zhihuishu.com/`（或 `user_open_tabs` 接管已登录标签）。
- [ ] 点首页「我的学堂」：优先 `dom_cua_click` 点 `href=https://onlineweb.zhihuishu.com` 的节点。
- [ ] 截图超时就 `tab_reload` 一次；以截图出现「AI智慧课程中心 / 我学的课」课程网格为准，别只看 URL。
- [ ] 按课程名定位卡片中心，`cua_click`；首次没生效就重试一次。
- [ ] `user_open_tabs` 找新开的 `wisdom-mooc.../study/index?recruitAndCourseId=<id>` 标签 → `tabs_claim`，**记下 `recruitAndCourseId`**。
- [ ] 点右上「菜单」（田字格图标）→ 面板展开，确认 12 项。
- [ ] 点第一行第三个「掌握度分析」（奖杯图标）。**不要点「作业考试」**。
- [ ] `user_open_tabs` 找新开的 `/study/analysis?...` 标签 → `tabs_claim`。
- [ ] 截图读基线：知识点总数 / 平均掌握度 / 薄弱点 / 遗漏点 / 免考 / 能力达成度 / 饼图占比。
- [ ] `mastery.py init --course "…" --url "<分析页URL>" --channel edge-extension --file <台账路径>`。

> **断点续跑**：台账里已有 `analysis_url` 时直接 `tab_goto` 到该 URL，跳过 B 的前 8 项；但仍要重新 `browsers_list` 确认**同一个 Edge 扩展实例**并 `tabs_claim`。换通道时所有坐标作废。

- [ ] 一屏记完再滚动下一屏，重复直到页面底部或达到上限。

## D. 逐知识点拉满（循环）

对每个 `pending` 项：

1. [ ] 重新截图（提交返回后页面会回顶部 → 重新下拉），用**最新**坐标点未满格子。
2. [ ] 单独再截一张图，确认浮层：「掌握度：X%」+「去提升」；免考提示 → `skipped_exempt` 跳过。
3. [ ] 点「去提升」→ 再截一张图等自测题浮层加载完。
4. [ ] 读顶部「测试题目」标签 + 右侧答题卡题量；红线扫描（计分 / 作业 / 考试 / 监考 / 人脸 / 验证码）→ 命中立即停。
5. [ ] 逐题：截图读题干 + 题型 + A–D → 双答案交叉判题 → 点选（多选逐个点）→ 复核选项高亮与题号变深紫。
6. [ ] 用答题卡跳题补齐 / 回查存疑题；确保**所有题号深紫**。
7. [ ] dry-run → 输出答案清单，停在这里。否则点「提交」一次，再截图等结果页。
8. [ ] 结果页读「掌握度 / 总题数 / 已答对」：全对 → `done`；未全对 →「查看作答记录与解析」纠错重做（最多 2 轮）→ 仍不行 `partial`。
9. [ ] 点左上返回箭头 → 分析页顶部 → 截图读基本信息，确认遗漏点减少、平均掌握度上升；没变 → `unverified` 停下。
10. [ ] `mastery.py record` 写结果；`mastery.py summary` 看进度。

## E. 收尾

- [ ] 全部未满格子处理完 + 基本信息「遗漏点 = 0」「薄弱点 = 0」→ `ALL_DONE`。
- [ ] `mastery.py summary` 出汇总：done / partial / skipped_exempt / unverified 各多少、平均掌握度变化、浏览器通道。
- [ ] **按 SKILL.md「输出要求」按提问范围回答用户**，答完即止；阶段 P 结论、台账路径、截图清单只在相关时才附在末尾。
- [ ] **仅实况通道且确实产生过截图**：先 `cleanup_screenshots.py list --file <清单>` 复核待删数量；数量与本次截图次数相符 → `cleanup_screenshots.py finish --file <清单>`；数量明显偏大或出现无关图片 → 改 `finish --file <清单> --keep` 只列不删并报告，不调大上限盲删。C/D 通道跳过，等价收尾检查是 `Glob` 一次 `~/.workbuddy/blobs`。
- [ ] 保留受控标签与台账，不调用关闭 / 清理类工具，方便下次续跑（如确需 `tabs_finalize` 必须带 `keep`）。截图缓存清理与保留标签不冲突：一个清本地图片，一个留浏览器会话。

## 常见故障速查

| 症状 | 一句话处理 |
|---|---|
| `mcp__browser__*` schema 全部加载不到 / 连接器列表为空 / 桌面层未安装 | **正常沙箱场景**，直接跳 F 节按提问范围交付；不引导安装、不追问、不停止 |
| `browsers_list` 里没有 Edge 扩展 | 用户要实跑且可安装 → 引导「设置 > 智能体 > 浏览器操控 > Microsoft Edge > 前往安装」安装启用 WorkBuddy Edge 扩展程序；否则跳 F 节 |
| 拿了第一个 `browser_id`，找不到已登录标签 | 误取内置 IAB；按 `type=extension` + `family=edge` + `user_tabs` 重挑并重跑阶段 P |
| `extension_disconnected` / `host_restarted` | 从 `browsers_list` 重新确认同一 Edge 实例并重新 `tabs_claim`，不复用旧 `tab_id`；恢复不了仍交付离线部分 |
| 点卡片没跳转 | 重试一次；或 `cua_execute` 合并点击 + 截图；查 `user_open_tabs` 是否开了新标签 |
| 开出两个重复标签 | 别连点；选 `selected:true` 的那个 claim，另一个忽略 |
| 截图半透明 / 浮层叠影 | 动画中间态，单独再截一张 |
| 点「去提升」后像没反应 | 再截一张，自测题浮层在异步加载 |
| 点「提交」后还是题目 | 再截一张，结果页在加载；别连点提交 |
| 滚动报超时 | `dom_cua_scroll` → `PageDown` → reload 后重试；每次滚动后截图确认 |
| 截图报 `provider invocation timed out` | `tab_reload` 恢复 |
| 提交后基本信息没变 | `unverified` 停下报告，不重复提交 |
| 出现「作业考试 / 计分 / 监考」 | 零点击停止，交还用户（真红线） |
| 登录态失效 | 提示用户本人重新登录，不自动重登；仍按 `delivery` 交付离线可答部分 |
| 用户说「停」 | 立即停，**先回答用户已问的问题**；有截图才清理 |
| `finish` 报「超过 --max-delete 上限」 | 不要调大上限盲删；`list --verbose` 复核，确认后改 `finish --keep` 交还用户决定 |
| 找不到截图清单 | 实况通道漏跑 `begin`；本次不追加清理（会误删历史缓存）。C/D 通道本来就不该有清单，不算故障 |
| 清理后历史对话缩略图不显示 | 正常副作用，平台数据与台账不受影响；需要复盘用 `finish --keep` 保留截图 |

## 不要做的事

- 不要默认取 `browsers_list` 的第一个实例，也不要在无提示的情况下改用内置 IAB。
- **不要因为浏览器工具 / 登录会话 / 桌面层 / 插件缺失就停止或只交一份阶段 P 报告**——落 C/D 通道继续交付。
- **不要**在用户只问页面标题 / 提示异常时夹带阶段 P 结论表、自检表、台账路径、截图清单、下一步引导。
- **不要**在用户已声明沙箱 / 免确认时索要课程名、索要提交授权、要求安装扩展或回复「继续」。
- 不要凭记忆坐标连点；不要用上一屏 / 上一次运行 / 换通道前的坐标。
- 不要用 DOM 快照去找课程卡片 / 菜单项 / 热力图格子 / 题目（本链路快照基本为空）。
- 不要点「作业考试」「退课」「交卷 / 提交成绩」。
- 不要调题库 / 搜题接口、不要读页面源码或网络请求找答案。
- 不要为了验证逻辑去重做已拉满（绿色）的知识点。
- 不要自动删除台账、不要关闭用户标签、不要代替用户安装浏览器扩展或登录。
- 不要整目录删除 `~/.workbuddy/blobs`、不要用 `rm -rf` / 通配符批量删截图、不要删台账与清单之外的文件、不要扫用户剪贴板图片；清理只走 `cleanup_screenshots.py finish`，且只在实况通道产生过截图时执行。
- 不要「先跑完清理再回答」：用户问的东西先答完，清理结果只是可省略的末尾补充。
